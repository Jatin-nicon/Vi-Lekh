# Proposal

## Why

Currently, contributors and developers must connect to cloud Firebase infrastructure to test authentication and role workflows, hindering offline development, isolated testing, and smooth contributor onboarding. Furthermore, the repository lacks automated testing infrastructure with Vite and Vitest to run fast component and unit tests for client code and API clients.

Introducing the Firebase Auth Emulator and a Vitest-based testing pipeline provides complete local independence, zero cloud lock-in for local development, and modern test automation.

## What Changes

- **Firebase Emulator Configuration**:
  - Add `firebase.json` configuring the Firebase Auth Emulator (port 9099) and Emulator UI (port 4000).
  - Update `src/lib/firebase/config.ts` to connect client-side Firebase Auth to the emulator when `NEXT_PUBLIC_USE_FIREBASE_EMULATOR="true"` or `process.env.NODE_ENV === "test"`.
  - Update `server/src/auth/firebase-admin.service.ts` in the NestJS backend to recognize `FIREBASE_AUTH_EMULATOR_HOST` so tokens generated by the emulator are accepted in local development and automated test runs.
  - Add root npm scripts `emulators:start` and `emulators:exec` for running the emulator suite.
- **Vite & Vitest Integration**:
  - Install `vite`, `vitest`, `@vitejs/plugin-react`, `jsdom`, `@testing-library/react`, and `@testing-library/jest-dom` as devDependencies in root `package.json`.
  - Add `vitest.config.ts` configured with `jsdom` test environment, setup files, and `@/*` path aliases aligned with `tsconfig.json`.
  - Create `src/test/setup.ts` to configure testing library matchers and mock browser APIs.
  - Add npm test scripts: `test`, `test:watch`, and `test:coverage`.
  - Provide initial unit and component test suites validating auth context, API client, and core utilities.

## Capabilities

### New Capabilities
- `automated-testing`: Defines test execution behavior, test environment isolation via jsdom and Vitest, and coverage reporting for client components and modules.

### Modified Capabilities
- `access-control`: Specifies that authentication flows, profile initialization, and server-side token verification SHALL support the local Firebase Auth Emulator in offline and testing environments.

## Impact

- Root `package.json` devDependencies and test scripts.
- Root configuration files: `firebase.json`, `vitest.config.ts`, `src/test/setup.ts`.
- Environment configurations in `.env.local` and `server/.env.example`.
- Frontend Firebase initialization in `src/lib/firebase/config.ts`.
- Backend Firebase Admin initialization in `server/src/auth/firebase-admin.service.ts`.
